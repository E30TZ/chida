# Security policy

## Reporting a vulnerability

Please report security issues through GitHub: open a private security
advisory on this repository (Security tab, "Report a vulnerability") if
that is available to you, or open a regular GitHub issue describing the
problem in general terms and ask for a private channel before sharing
exploit details.

There is no dedicated security email address for this project, and any
address claiming to be one should not be trusted unless it is listed in
this file.

Please include, as far as you can:

- The Chida version and your operating system.
- What the issue allows an attacker to do.
- Steps to reproduce, ideally with a small sample project file.

## Scope notes

- Chida project files (`.chida.json`) are data. If rendering or opening
  an untrusted project file crashes Chida or escapes the project
  folder, that is a security issue worth reporting.
- Applications generated by Chida are starting points owned by their
  creators. One known and labelled weakness ships on purpose as a
  visible stub: password hashing in generated code is salted SHA-256
  and the generated source says to replace it with Argon2id before
  production use. Reports about that stub itself are not needed;
  reports that generated code is unsafe in other ways are welcome.

## Supported versions

Only the latest release is supported with fixes.
